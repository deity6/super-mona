1 · 头号彩蛋：WebGLSuperMona（hero 里藏的游戏）

01不是动效，是个真游戏

首页 hero 下方那块区域，你看到的是一层浅色点阵。它的 DOM 是：

<div class="Hero_HeroArtwork">
  <div class="WebGLSuperMona_Wrapper"
       style="--grid-x: 94; --grid-x-narrow: 67; --grid-y: 26;">
    <canvas data-engine="three.js r182" width="1524" height="422">

入口按钮文案直接点明了它的用途：play_super-mona_while_you_wait/——"等 Keynote 开始前的空档，来一把 Super Mona"。

从压缩代码里挖出的状态机：

lives: 3, score: 0, superSeconds: 0,
movement: "resting", gameOver: false   // 3 条命 / 分数 / 结束态

配套 UI 组件（全部有独立 CSS 类）：HudLivesHeartControlsControlKeyScoreSoundButtonGameOverScoreBoard

操作键位：ArrowLeft ArrowRight KeyA KeyD，带音效开关和结算面板。WebGL 不可用时降级显示 FallbackImage 静帧。

022444 个方块，一次 draw call

关键性能手法是 Three.js 的 InstancedMesh——一块几何体渲染 2444 次，每个实例只传位置/缩放/颜色矩阵：

// 网格配置（宽屏 / 窄屏两套）
{gridX: 94, mona: {x: .5,  y: -.11, scale: .075}}
{gridX: 67, mona: {x: .2,  y: -.05, scale: 1.7 * scale}}   // narrow

// 实例化网格：new InstancedMesh(geometry, material, count)
this.instanceMatrix = new Float32Array(16 * count)

验证：canvas 1524 × 422 ÷ 94 ÷ 26 = 每格 16.2 px 正方形。你在页面上看到的"点阵"，每个点就是一个方块。

2 · Tracers：彩色方块沿按钮边框绕圈

这是最容易被误认成"鼠标跟随"的效果。真实机制：5 个方块沿按钮的矩形周长匀速跑圈，每块延迟 0.15 秒错开，转角处自动旋转 90°。

COLORS = ["#c05200","#583af7","#ae85ff","#bba00a","#08872b"]
DUR    = 3.6s                     // 单块跑完一圈
STAG   = 0.15s                    // 相邻方块的延迟
TOTAL  = 3.6 + 0.15 * 4 = 4.2s    // 整段动画时长

// 沿矩形周长取点（上边 → 右边 → 下边 → 左边）
at(prog):
  o = (prog + W/2) mod 2(W+H)
  o < W        → 上边，rotate 0
  o < W+H      → 右边，rotate 90
  o < 2W+H     → 下边，rotate 0
  否则          → 左边，rotate 90

// 关键：不是匀速，带起停缓动
ease(e) = e - 0.8/(2π) · sin(2πe)

三个工程细节值得抄：

  • 用 IntersectionObserver 判断进入视口才开始跑，跑完给宿主元素加 data-tracing 属性，由 CSS 接管终态
  • prefers-reduced-motion 命中时整段跳过
  • 用 ResizeObserver 重算按钮尺寸，窗口变化不会跑偏

⚠️ 注意：这个效果只在活动直播期间挂在绿色的「Watch now」按钮上。现在活动前，按钮是 Get passes，所以你在页面上看不到它。

3 · 其余四件值得看的小玩意

解码打字机

所有标题（stay-tuned/、october 28–29 / san francisco, CA）都是逐字符"乱码 → 定格"：

charset = "ABCDEFGHIJKLMNOPQRSTUVWXYZ
  0123456789.!@#$%^&*()_+-=[]{}|/;<>?"

GSAP timeline 驱动，每个字符先随机 2–3 次再落定，配一个闪烁光标元素。减速偏好开启时直接显示终态。

HeaderCountdown

顶部那条绿色横幅是实时倒计时，四段数字逐秒跳动：

universe2026-streams-in/
12 : 10 : 28 : 30

组件拆成 Unit / Value / Separator 三个原子，方便单段做动画。

页脚第二块 3D

页面滚到底（y≈10257）还有一块 WebGLFooterCta，984×492 的独立 Three.js 场景，和 hero 那个互不干扰、懒加载。

拖尾区域标记系统

代码里导出两个类名常量做"区域声明"：

trailAnimationArea    // 参与拖尾
trailAnimationIgnore  // 忽略拖尾

hero 插画和 SuperMona 区都挂了 Ignore——因为这两块自己有 WebGL，不让 DOM 层的拖尾干扰。

5 · 如果要搬进 SOFT LAB

效果移植难度建议
Tracers 方块绕边框 很容易 纯 DOM + rAF，无需任何 3D 库。算法已完整解出（本页 demo 就是可跑的复刻）。适合挂在按钮或卡片边框上，做"待机态"小动效。
解码打字机 很容易 不依赖 GSAP，几十行 rAF 就够。跟现有 changelog / 标签体系气质吻合，可直接用在版本号或实验标题上。
方块网格（94×26） 中等 需要 Three.js + InstancedMesh。若只是展示（不做游戏），可以用 Canvas 2D 或 CSS Grid 近似，成本降一个量级。
WebGLSuperMona 游戏 偏重 要复刻得重写：网格物理 + 角色碰撞 + HUD + 音效 + 移动端触控。作为"第五个实验"可以立项，但建议先做静态方块网格探路。
Primer Brand 动画系统 可直接装 MIT 许可，npm i @primer/react-brand。但要评估：它的设计令牌和 SOFT LAB 现有纸色体系是否冲突——大概率只借鉴 API 设计，不直接引入。
三个坑提醒：
  • 该站的 SSR HTML 里没有任何 canvas。只抓静态 HTML 会得出"这站没有 3D"的错误结论——必须实际渲染。
  • 压缩代码里搜关键词会被同名撞车骗到：mona 147 次其实全是字体名 mona-sans；rive 104 次全是 Primer 的 River 组件，不是 Rive 动画库。
  • Primer Brand 是 MIT，但只覆盖设计系统层。WebGL 实现没有开源，照着扒只能自己重写。
